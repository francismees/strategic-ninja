# Behavioural evaluation: 17 September 2026

Status: **run, with recorded failures and one repair cycle**. This is provisional, model-judged evidence. It does not show that the skill improves real strategy work.

## Setup

| Item | Detail |
|---|---|
| Host | Claude Code desktop app (macOS). Responses generated by general-purpose subagents inheriting the session model (Claude Opus 5 family; exact model not independently confirmed per agent) |
| Conditions | **Baseline:** the prompt and fixture files only, with an instruction not to open other files or search the web. **Skill:** identical, plus an instruction to read `SKILL.md` and follow it, loading only the modules it routes to. Both could use Bash for calculations where data was attached |
| Deviation from real use | The skill was loaded by instruction, not by Claude Code's native trigger. Automatic triggering was not tested |
| Cases | 12 of the 25 development cases in [../../behavioral/cases.json](../../behavioral/cases.json) (BEH-01, 02, 05, 06, 08, 12, 13, 16, 17, 20, 22, 25), plus **2 held-out cases** ([heldout_cases.json](heldout_cases.json)) written by a separate agent that had not seen the skill |
| Tiers covered | 7 standard, 5 adversarial, 2 ambiguous |
| Fixtures | Copied to a neutral scratch folder outside the skill |
| Blinding | Response order randomised per case (seed 20260917; mapping in [run1/blind_mapping.json](run1/blind_mapping.json)). One judge agent per case received only the rubric, the case, any fixture files and the two blinded responses, not the skill |
| Judging | [../../behavioral/rubric.md](../../behavioral/rubric.md): each expected item MET, PARTLY MET or NOT MET; each prohibited item PRESENT or ABSENT; a case verdict; unsupported material claims; human correction needed; a pairwise preference |
| Run 2 | After repairs, the skill condition was re-run on 5 cases and judged against the **same** baseline responses by fresh judges. Order was alternated to balance position (the seed had placed all five skill answers first; see [run2-after-repair/blind_mapping.json](run2-after-repair/blind_mapping.json)) |

Raw material: responses in `run1/outputs/` and `run2-after-repair/outputs/`; judgements in the matching `judgments/` folders; all verdicts in [verdicts.json](verdicts.json); tables in [verdict-tables.md](verdict-tables.md).

Notes:
- The unsupported-claim counts are noisy. In BEH-08, all five claims flagged against the skill were correct TCRA and World Bank figures (verified during the build), which the judge could not check.
- **Judge instability.** In run 2, a different judge rated the *same* BEH-06 baseline answer PASS, where run 1 had rated it FAIL. Single-judge verdicts should be treated as provisional.

## Run 2 results (after repair; 5 cases)

| Case | Words: baseline / skill v1 / skill v2 | Mentions of the skill in v2 | Verdicts (baseline / skill) | Judge preferred (v1 → v2) |
|---|---|---|---|---|
| BEH-02 | 1,057 / 1,457 / 1,076 | 0 | PASS / PASS | skill → **baseline** (narrow) |
| BEH-06 | 3,064 / 2,405 / 1,966 | 0 | PASS / PASS | skill → skill |
| BEH-13 | 2,083 / 2,392 / 1,993 | 0 | PASS / PASS | baseline → baseline |
| BEH-16 | 1,121 / 1,783 / 1,481 | 0 | PASS / PASS | skill → skill |
| BEH-17 | 1,414 / 3,215 / 1,924 | 0 | PASS / PASS | baseline → **skill** |

Across the five re-run cases:
- Mentions of the skill fell from 4 of these 5 answers to 0.
- Skill answers got shorter in all five, but are still longer than the baseline in BEH-16 and BEH-17.
- Unsupported claims flagged: baseline 25, skill 8.

The preference flip on BEH-02 is informative. The judge preferred the baseline's full three-way price/volume/mix split and finished board paragraph. The skill's v2 answer did not separate mix from volume, and it questioned whether carton counts across pack sizes are a common volume unit. The judge treated that as steering away from the decline on an unverified assumption.

With one run per condition, a single flip in either direction is not a reliable signal.

## Limitations

- Small sample: 14 cases, one generation per condition (plus 5 re-runs). No repeated runs to measure variance.
- The same model family generated and judged. Judges disagreed with each other on at least one case. No human strategist reviewed the outputs.
- Development cases were written by the skill's builder, with the skill's rules in mind. Only 2 held-out cases were used.
- The skill was loaded by instruction rather than by native triggering, in subagents rather than real user sessions.
- Judges could not verify real statistics, so they counted some correct figures as unsupported.
- Deterministic results (arithmetic, schemas, links) are reported separately and are not evidence of strategic quality.
